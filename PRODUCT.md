# Cypher for Hive and Atlas

An owner-operated agent workspace with persistent shared conversations, a cloud worker, configurable models, media tools, and remote MCP connections. Cypher uses the original monochrome logo and binary-lens animation while retaining the Open GrokBot backend and capabilities. Earlier Grok screenshot directions are historical; example conversations and local fixtures are not real product data or authorization to send messages. No pixel-exact or xAI feature-parity claim is made.

## Current product

The default entry point is a task prompt with Ask anything and Create an image. Agent creation starts from role presets with filled instructions, optional names, named model menus, and progressively disclosed custom configuration. OpenAI GPT-6.1 Sol is the main-conversation default. Model requests use the configured OmniRoute connection, or a direct provider key when OmniRoute is unset. There is no Vercel AI Gateway inference path.

The default Agent lounge contains six agents: Coordinator, Builder, Researcher, Writer, Reviewer, and Runner. The coordinator delegates up to three concrete assignments, specialists receive their own assignment, and the coordinator synthesizes their results. Automatic specialist routes are checked against OmniRoute's authenticated live model catalog; missing routes or unsupported inputs use the specialist's declared fallback. Other rooms support 2–6 agents and bounded rounds.

Messages accept up to four files and 3 MB combined: PNG/JPEG/WebP, PDF, UTF-8 text, common audio formats, and MP4/WebM/MOV. PDFs are converted into page text and images; audio and video speech are transcribed; video files and public YouTube/Instagram links can be analyzed as timestamped sampled frames and speech. Those media paths use OmniRoute or a direct OpenAI connection and report capability limits without substituting captions for evidence. Image generation is supported; video generation is not currently offered. Run controls configure response length, temperature where supported, tool-step limits, rounds, and main-panel typeface. Inter Variable is self-hosted. Jobs persist, expose cancellation, and report worker readiness through a database heartbeat. Cancellation stops future execution but cannot undo an external action already completed.

## Appearance, goals, and channels

The Cypher workspace uses the platform font stack, opaque neutral controls, and light or dark appearance. App-owned brand and action colors are monochrome: graphite on light surfaces and light ink on dark surfaces. Blue and purple are not brand options. The old accent selector is removed; loading a saved accent cannot restore colored actions. Browser-local preferences retain message text size, desktop message width, agent-list density, and interface motion. Inter and Georgia remain optional conversation typefaces; Inter is not a newly introduced brand face. Preferences do not imply cross-device account synchronization.

Cloud goals persist in the database and schedule finite runs in the hosted worker. Each goal specifies an objective, evidence-based completion criteria, room, Sol/Luna manager, interval (minimum 15 minutes), and run allowance. The UI offers 1–20 runs and 15–1440 minute intervals; the API permits intervals up to seven days. Defaults are three runs, one hour apart. At most ten goals may be active. Completion requires the completion tool and a successful task. Pause cancels pending work or requests running-task cancellation; failed/interrupted work blocks further runs until explicit resume/retry. Exhausted or completed goals cannot be resumed. Agent-created follow-up goals are limited to three runs, one per task, with no nested goals.

Webhook channels accept authenticated, deduplicated external tasks into a chosen room and optionally deliver finished results through a signed HTTPS outbox. Limits are ten new events per channel per minute, a workspace queue cap of 20 pending/running tasks, and three outbound delivery attempts. Channel keys are displayed once; signed delivery and service authentication remain distinct. Public frontend endpoints remain subject to Vercel deployment protection. Channels do not create private-app OAuth connections or bypass external account permissions.

## Connections

Curated connectors and the live MCP Registry can be searched from one panel. Registry search covers thousands of listings; listings are discovery data, and only compatible hosted endpoints can be connected directly. Public HTTPS Streamable HTTP servers can use the provider's consent flow; local packages and unsupported transports show setup requirements. Connected tools can be searched and called by agents with Plugins enabled. Optional bearer tokens are encrypted server-side; connecting requires user approval and may grant tools that read or change external service data.

The Connections panel also lists Hive/Atlas Vercel variable names and configuration states, never secret values. The current deployment preparation imported 43 available values (35 retrieved individually plus eight earlier) and inventories 177 names; protected variables that could not be exported remain Needs link. Inventory is not proof of service integration or credential validity.

Model setup is reachable from the home composer and conversation settings. Manual model menus also include five OmniRoute cloud routes for coding, reasoning, vision, fast, and all-purpose work; OmniRoute resolves them against its live catalog and the connected provider account sets availability and pricing. In OmniRoute mode, the installation owner can check the saved OpenAI, Gemini and Claude connections, open a fresh official Google verification link when required, and retest after completing the provider check. Checks are queued in PostgreSQL, continue after the dialog closes and recover for at most three worker attempts. Only a real model response enables a managed route; opening a verification link never marks access verified. Google account checks remain human steps. New Gemini or Claude API keys are encrypted and checked before replacing a saved API account; a rejected key preserves the existing connection. Other tenants cannot operate shared installation credentials or read verification challenges. Direct mode retains the one-request Gemini test and provider setup links.

The active repository-root `vercel.json` defines a Next.js frontend, private Python container backend, internal service binding, and a persistent worker daemon. The authorized Atlas native PostgreSQL credential is configured for isolated `grokbot` state. Hive and Atlas configuration retain separate prefixes; secrets stay server-side and are not injected into sandboxes. The managed Vercel Sandbox adapter handles shell/files; Docker remains an alternative and Playwright browsing runs on the hosted backend.

Earlier releases verified selected database, worker, model, browser, sandbox, and MCP paths. Those results do not prove the current release or every model, provider, media route, sandbox, or connected service; current build and smoke-test results are recorded in `deployment/VERIFICATION.md`.

## Website-based plugin connections and workspace layout
The search panel combines curated connectors with live MCP Registry paging. Where a server publishes a usable HTTPS endpoint, connect begins the provider's OAuth discovery and consent flow. Consent pauses durably in PostgreSQL; a browser-bound HttpOnly cookie, state, issuer, PKCE, expiry, and one-use callback protect completion. Access and refresh tokens are encrypted. A plugin becomes enabled only after tools are discovered. Some providers require keys, client registration approval, paid plans, or unsupported authentication; a listing is not a successful connection or a universal one-tap guarantee. The public callback origin defaults to the production GrokBot hostname and is configurable with GROKBOT_PUBLIC_URL.

The sidebar resizes on desktop, docks left/right by drag or button, collapses to icons, and remembers the layout in this browser. Keyboard resizing and a collapse shortcut are available. Agents can be pinned and filtered by actual working status; search covers names, roles, descriptions, and room titles. These controls do not change model capabilities or provider permissions.

Plugin execution uses two bounded routing tools: search enabled service tools, then invoke by stable service/tool identity. Tool discovery follows MCP pagination. Connected services distinguish protocol discovery from completed read-only smoke calls; Test tools reports persisted pass/fail and elapsed time for supported providers. API-key connections retain the provider’s required header. The 500-entry catalog is discovery coverage, not 500 authorized or execution-verified accounts.

Workspace setup offers an AWS CloudFormation template for a private, single-host workspace with PostgreSQL, Redis, HTTPS and owner authentication. Creation requires the AWS owner to review and launch the stack; no deployment is claimed until AWS succeeds. Hosted ChatGPT plan sign-in is unavailable without an approved client.

## Google permissions and native MCP tools — October 24, 2026

Google identity sign-in now leads to an optional service-permission screen. Users choose Gmail, Calendar, Drive (including Docs, Sheets and Slides), Contacts, and Tasks, then grant access on Google’s actual OAuth consent page. This uses a dedicated AI-agent OAuth client, PKCE, a browser-bound HttpOnly cookie, tenant-scoped one-use state, and encrypted refresh tokens. Returned scopes and successful read probes determine the enabled services; a catalog entry or attempted consent never counts as connected. Existing grants survive failed replacement consent. Disconnect revokes the Google grant. Background refresh supports existing cloud tasks while the app is closed.

The native Google Workspace plugin exposes bundled Google API operations through the existing tool search/call path and an authenticated, tenant-scoped MCP endpoint. Tools include readable email and unsent-draft helpers, calendars/events, files, Docs/Sheets/Slides, contacts and tasks. Gmail sends, file-sharing changes and event writes with attendees require in-task approval. External content is untrusted source data. No email or invite is sent by the connection flow itself. The Google project’s public verification status and limits remain provider-controlled; enabling the code does not mean Google has verified the application or every provider in the catalog works.
